== Method
bench_particles runs the client's particle code (client/particles.c) without a window.
Every tick (dt = 1/60 s) it updates every particle, then respawns bursts until
the count is back to N (steady state: ~1 in 75 particles dies and is replaced
per tick); 120 untimed warm-up ticks first. Each run does about 200000000 particle
updates (ticks = 200000000 / N, at least 300). Every configuration gets the same
random numbers, and the checksum column shows they end with the same particles.
10 runs per configuration and N, interleaved; one process per run under
perf stat, pinned with taskset (CPUs column). Hardware counters count the whole
process (set-up, warm-up and the timed ticks).
Step #5 (TLP): soa AVX2 build, update split over a worker pool (common/
worker_pool.c): cache-line-aligned chunks, two barrier waits per tick, dead
particles removed inside each chunk in parallel, then a short serial step
closes the gaps between chunks. Respawning is serial. One thread per physical
P-core (CPUs 0,2,4,6,8,10,12,14; no hyper-threading siblings).
